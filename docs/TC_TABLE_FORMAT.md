# TC_TABLE v1 —— 热电偶分度表文件格式规范

> 这是"表里存数据的协议"。任何来源的分度表（NIST 官方、IEC/ASTM/GB 标准、
> 厂家 PDF、单支标定数据）只要转成这个格式，上位机就能直接加载、校验、插值。
>
> 工程内已有的 5 张表（K/J/T/E/N）由 `tools/nist_tc_tables.py` 从 NIST SRD 60
> 自动生成，**默认使用 K 型**。

---

## 1. 文件位置与命名

```
tables/
├── manifest.json          清单: 默认分度号、每张表的点数/范围/sha256
├── tc_type_k.csv          K 型  ← 默认
├── tc_type_j.csv          J 型
├── tc_type_t.csv          T 型
├── tc_type_e.csv          E 型
└── tc_type_n.csv          N 型
```

命名必须是 `tc_type_<字母>.csv`（小写字母），程序靠文件名识别分度号。

---

## 2. 文件结构

**纯文本、UTF-8、LF 换行**。分两段：注释头 + 数据体。

### 2.1 注释头（每行以 `#` 开头）

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| `type` | ✅ | 分度号，单字母：`K` `J` `T` `E` `N` `R` `S` `B` … |
| `direction` | ✅ | `T2E` = 温度→电势（分度表，本标准默认）；`E2T` = 电势→温度（厂家逆表） |
| `ref_temp_C` | ✅ | 参考端温度，标准表都是 `0` |
| `temp_unit` | ✅ | 固定 `C` |
| **`emf_unit`** | ✅ | **必须是 `uV`** —— 见第 4 节的坑 |
| `temp_min` / `temp_max` | ✅ | 覆盖范围 °C |
| `step_C` | ➖ | 标称步长（允许非均匀，实际以数据体为准） |
| `points` | ✅ | 数据行数 |
| `standard` | ➖ | 依据的标准 |
| `source` | ➖ | 数据来源（文件/网址/厂家料号/标定日期） |
| `max_dev_vs_reference_uV` | ➖ | 与标准参考函数的最大偏差（自检证据） |
| `created` | ➖ | 生成时间（UTC, ISO 8601） |
| **`sha256`** | ✅ | **数据体的 SHA-256**，读取时强制校验 |

### 2.2 数据体

第一行是列名（固定写法），随后每行两个数：

```
temp_C,emf_uV
-270,-6458.0
-269,-6457.0
...
1372,54886.0
```

* 两列用逗号分隔，**不允许空行/多余列/表头重复**
* `T2E`：温度列严格递增；电势列单调不减
* `E2T`：电势列严格递增（列顺序相反，即 `emf_uV,temp_C`）
* 步长可非均匀（厂家表常见 1 °C 起始、10 °C 结尾）

完整样例（K 型表头）：

```
# TC_TABLE v1
# type       = K
# direction  = T2E
# ref_temp_C = 0
# temp_unit  = C
# emf_unit   = uV
# temp_min   = -270
# temp_max   = 1372
# step_C     = 1
# points     = 1643
# standard   = ITS-90 (NIST SRD 60) / IEC 60584-1 / ASTM E230 / GB/T 16839
# source     = NIST SRD 60 type_k.tab.txt
# max_dev_vs_reference_uV = 0.499
# created    = 2026-10-04T10:28:44Z
# sha256     = 678e97203fd1fb16d00bbb6521375269c8aee0134df4c7388dbf24c4c65a0f3a
temp_C,emf_uV
-270,-6458.0
...
```

## 3. 强制校验（加载时执行，不通过就拒绝加载）

| # | 规则 | 目的 |
| --- | --- | --- |
| 1 | `emf_unit == uV`、`temp_unit == C` | 防单位错（第 4 节） |
| 2 | `sha256(数据体)` 与头部一致 | 防手改数字 / 传输损坏 |
| 3 | 温度列严格递增 | 保证插值可用 |
| 4 | 电势列单调不减 | 保证求逆唯一（例外见第 5 节） |
| 5 | 至少 2 个点、列数为 2 | 基本格式 |
| 6 | 数值可解析 | 防残留的表格线/单位文字 |

生成端的校验（`tools/nist_tc_tables.py`）更严格，还会做：

* 表值与**文件自带参考函数**逐点比对（容差 2 µV）→ 抓"列错位/漏读一格"
* K 型额外用 **5 个硬编码锚点** + **固件 `thermocouple.c` 的独立系数实现**比对
* 结果写进头部的 `max_dev_vs_reference_uV`，可追溯

---

## 4. ⚠️ 单位坑：为什么 `emf_unit` 是强制字段

NIST 原始文件里的**逆函数系数是 mV 基准**，而固件 `thermocouple.c` 是 **µV 基准**，
两者相差 $1000^{\,i-1}$。例如 K 型逆函数第 2 项：

| | 系数值 |
| --- | --- |
| NIST 原文件（E 用 mV） | `-1.1662878E+00` |
| 固件（E 用 µV） | `-1.1662878E-06` |

**照着 NIST 文件把系数直接抄进 µV 代码，温度会差几个数量级，而且不会报任何错。**

所以：表文件必须显式声明 `emf_unit`，加载器强制检查，缺了或写成 `mV` 直接拒绝。
（有人想用 mV 表？请先自己乘 1000 转成 µV 再存，别让歧义进入数据。）

## 5. 已知的物理限制（不是错误）

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| N 型 −270…−260 °C 有**相邻电势相等** | 表分辨率 1 µV，而该处热电率只有 ~0.3 µV/°C，四舍五入后打平 | 求逆时取该平坦段的**温度均值**；此区间温度不确定度 ±0.5 °C，是表本身的信息极限 |
| 格点之间往返有 ~0.01–0.03 °C 误差 | 1 µV 量化 ÷ 局部斜率（1000 °C 处 39 µV/°C → 0.026 °C） | 任何插值都无法突破；要更准只能用更细的表 |
| 线性插值在 1 °C NIST 表上比单调三次**略好** | 三次插值会放大 1 µV 量化噪声的斜率估计 | NIST 表两者皆可；**粗表（10/100 °C）用单调三次明显更准** |

## 6. 新增一张厂家表的标准流程

```
① 拿到数据（PDF 表格 / Excel / 标定报告 / 单支修正曲线）
② 转成两列文本 (温度, 电势)
     - 文本型 PDF：用 pdfplumber 抽表格
     - 扫描件：OCR 后**必须人工抽查**，且第 ③ 步一定要做
     - 只有系数：用系数重建整表（推荐，绕开逐度 OCR）
③ 规范化 + 校验  ← 关键步骤，缺了这一步等于埋雷
     - 单位统一成 µV（若是 mV 先 ×1000）
     - 温度基准统一成 0 °C 参考端
     - 单调性检查、与 NIST 同型号表逐点比对（偏差 > 阈值就报警）
④ 写成 TC_TABLE v1，放进 tables/tc_type_<字母>.csv
⑤ 用 pc_ui/table_selftest.py 跑一遍（会重新校验 sha256 与单调性）
```

> **绝不允许**跳过 ③ 直接把抄来的数字写成表。一个 OCR 错位就是几十度的静默误差，
> 而且它会一路带进 CSV、图表和结论里，事后极难发现。

## 8. 表是怎么被用的

```
        ┌─ 现在 ─────────────────────────────────────────────┐
固件 ──▶│ CMD=0x10 温度(float)  → 上位机直接画曲线/存CSV     │
        └────────────────────────────────────────────────────┘

        ┌─ 待办（需新增 CMD=0x12, 见对话说明）───────────────┐
固件 ──▶│ CMD=0x12 原始 µV + 冷端温度                        │
        │      ↓                                             │
        │  tc_table.TCTable.compensate_hot_junction()        │
        │      ↓                                             │
        │  温度(用你选的表算) → 曲线/CSV                     │
        │  CSV 同时存 µV 与温度 → 换表可离线重算             │
        └────────────────────────────────────────────────────┘
```

`pc_ui/tc_table.py` 提供的接口：

```python
from pc_ui.tc_table import TCTableSet, default_table_dir

tset = TCTableSet(default_table_dir())      # 默认 K 型
tb   = tset.get("K")                        # 或 "J" / "T" / "E" / "N"
tb.temp_to_emf(1000.0)                      # -> 41276.0 µV
tb.emf_to_temp(41276.0)                     # -> 1000.0 °C
tb.compensate_hot_junction(emf_uv, cj_c)    # 冷端补偿 (与固件同算法)
```

插值方式可选：`mode="pchip"`（默认，单调三次）或 `mode="linear"`（最快）。
